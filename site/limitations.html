Limitations

What is wrong with Horus right now. Published because a security project that hides its weaknesses is not making a security claim.

What is wrong with Horus right now.

Horus is research-grade, has not been independently reviewed, and should not be trusted with anything real. These are the open limitations worth knowing before you draw a conclusion about it. The authoritative list, with every closed entry and the pull request that closed it, is LIMITATIONS.md.

  • C-5Nobody reviews a change before it lands

    Claude writes most of the code and merges its own pull requests once every gate is green; the maintainer sets direction and decides the questions that touch the security model. No human reads a change before it merges. The automated side is extensive: the gating set is 136 checks with 4 exempted, each security property has a named witness, and each gate has a control arm that puts the defect back and must turn it red. But the 2026-07 critical finding passed every gate of its day, because the tests checked the property the author had in mind rather than the one the documentation claimed. The honest claim is "thoroughly automatically verified", not "independently reviewed".

  • 1.8Eleven system calls have no test that runs them

    91 of 102 system calls have their handler actually executed by the scripted session, the permission conformance suite, or the boot-modules session. The other 11 are each listed with a written reason, and a checked-in file classifies all 102 implemented syscalls, covered or not, so the number cannot quietly fall. The gap matters: four times, a probe written to run an uncovered handler found a real defect on its first boot.

  • 1.14A child's inherited pipe end escapes revocation

    Every capability a forked child receives is derived from its parent's, so revoking the parent's reaches it. The one capability a spawn wires in for standard input or output is not: the child's pipe end is a root of its own, and revoking the parent's end does not reach it. Nothing revokes a pipe end today, so this contradicts a stated property rather than exposing a live hole. The fix needs the pipe's end counts reconciled at the same time, and its design is written down.

  • 1.6The console is the one ambient authority

    Writing to standard output and reading a console line need no capability, by decision: every task has a standard output. The read side refuses once the console server owns the hardware, and the write side cannot reach the kernel log. Every other system call in the shipping kernel is authorised by a capability.

  • 2.6cMost gates still read kernel reports off a shared console

    The kernel writes a report one byte at a time to a serial line that a user-mode program also writes, so an unrelated program's output can land in the middle of it and a gate matching that report misses it. It has happened in CI. The kernel now has a diagnostic port that no capability names, so only the kernel can write it; four gates read it, and about twenty still read the shared console.

  • 2.9Measured boot is opt-in

    On a machine with no TPM the default build boots without measuring anything, and the boot log says so. A build with MEASURED_BOOT_REQUIRED=1 halts instead, and refuses a disk that was never sealed. Rollback protection is anchored in a TPM counter, so a volume formatted on a machine without one has the Merkle tree and nothing more.

  • 4An installed disk does not boot on its own

    The installer writes an encrypted volume over the whole disk, with no partition table and no bootloader, and the shipped programs live in the measured boot image rather than on the disk. An installed machine is started from Horus boot media, which finds and opens the volume. A GPT disk with an EFI system partition and programs pinned by hash in /bin is designed and not built.

  • 4Hardware support is narrow

    Horus installs onto legacy IDE disks and SD or eMMC storage, and it has installed onto a laptop's soldered eMMC. It identifies a SATA drive and cannot read or write one, has no NVMe or USB support, and so has no keyboard on a machine that offers no PS/2 emulation. One user-mode network driver completes an ARP exchange; there is no IP stack above it. A DMA-capable device is confined by the IOMMU where the machine has one; where it does not, the boot says so.

  • isoThe ISO does not rebuild to the same bytes

    The kernel image is byte-for-byte reproducible and gated on every merge. The ISO is not: grub-mkrescue writes a file named for the wall-clock second and embeds an identifier in the EFI loaders it generates. The one release so far, an alpha for developers, is an ISO and its checksum with no signature and no provenance, so nobody can check that it came from this repository's CI.

  • cryptoEvery primitive is unaudited

    ChaCha20, SHA-256, BLAKE2b, Argon2id and the AEAD are from-scratch no_std Rust checked against published test vectors. None has been independently audited and none is verified constant-time. They protect the measured-boot chain, every block of the encrypted store and every password at rest. Treat them as research code.

  • 5.5Formal verification is narrow

    Bounded Kani proofs cover capability revocation, the ELF validator and the page-pool reference counts, and most of them gate a merge. That is all of it: the kernel as a whole is not verified, and there is no TLA+ specification.

  • miscSmaller edges, all tracked

    A destroyed kernel object's memory is not reused until its budget is reset, which is not written. A program linked to the shared libc cannot fork. There is a monotonic clock at 10 ms resolution, deliberately, and no wall clock or timers. Any program a person runs can read the command lines they type, though not their passwords. Scheduling is a single shared pool with global locks, fine at eight CPUs and not beyond.

Where the line sits

Horus boots, installs onto a disk, runs an unprivileged init that supervises unprivileged servers and a shell, and enforces capability-based access control end to end, including across IPC and device access. The machinery that checks it (measured boot, adversarial CI, bounded proofs) is more mature than the operating system it checks.

This is a research kernel, not a shipping operating system. Nothing here should be trusted with anything real.
