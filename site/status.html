Compile-time ceilings still apply to most of the system: 256 capability slots per task, a 256-byte message, eight CPUs and a 16 GiB volume ceiling (the real size is read from the disk). The number of tasks is worked out at boot from the memory reserved for them.

What comes next.

The foundations are done. IPC is capability-addressed, uid 0 confers no kernel authority, every kernel object is paid for from a budget a task holds a capability to, and the interrupt, locking, journal and spawn-path work that made the kernel correct under several CPUs is finished.

Next, in order: the file server authorises by capability rather than by user id and mode; the installer copies the system onto the disk, where the loader runs only programs whose hashes are pinned in the measured boot image; the disk gets a partition table and a bootloader so it starts on its own; and accounts move into files owned by a user-mode authentication server. After that, the filesystem itself moves out of the kernel, onto a copy-on-write format.

The single highest-leverage change is not technical: a second person reviewing the capability paths. No human reads a change before it merges today.
