An operating-system kernel for x86-64, written in C and Rust

Authority is something you hold, not something you are.

In Horus, no program has any power by default. Reading a file, talking to a driver, creating anything in the kernel: each needs a specific, unforgeable token that the program was deliberately handed. There is no root that opens every door, and nothing is trusted because of who it claims to be.

Now installable. Horus installs onto a laptop's built-in eMMC storage, the soldered flash many small laptops use, as well as onto IDE and ATA disks. What that involves

What that changes

When a program on an ordinary system is compromised, the attacker inherits everything it was trusted with, which is usually a great deal. Horus is built so that the answer is: only the tokens that program held.

Nothing has power by default

Every privileged action names the token that authorises it. A compromised program gets its own tokens and nothing else.

How capabilities work

Failures stay contained

The filesystem and the console run as ordinary unprivileged programs, outside the kernel. A bug in one crashes that program, not the machine.

What runs where

Your data is sealed

The disk is encrypted, its key derived from your password with Argon2id, and the filesystem program never sees the key at all.

Storage and keys

Safe code where attackers aim

The parsing of untrusted bytes is memory-safe Rust, and the kernel's rules about who may do what are proved with Kani.

How it is checked

You can check what runs

The kernel builds to the same bytes every time, and the boot chain is measured into the TPM before the disk will unlock.

The boot chain

Claims come with proof

Every security claim names the test that proves it, and each gate is checked by putting its bug back on purpose to see it fail.

The method

Install it on real hardware

Horus is no longer only something you boot in an emulator. Its installer writes a working system onto a machine's own storage, encrypted by default, and the machine then starts from it on its own.

  • eMMC, the flash chip soldered into many small laptops, installed and booted on a Lenovo IdeaPad.
  • IDE and ATA disks, including the virtual disks QEMU and other emulators provide.
  • Not yet: NVMe and SATA SSDs. A machine whose only disk is one of those can run Horus live, but cannot install it.

Why new kinds of disk come quickly

Everything Horus does with a disk is written once, above a small interface that asks a driver for four things: read a block, write a block, fill a run of blocks, and make writes durable. The encryption, the integrity checks, crash safety and the filesystem sit above that line and are shared by every kind of storage.

So supporting a new kind of storage means writing one driver that answers those four requests, not reworking the system. eMMC support arrived exactly that way, and the same route is open for NVMe and SATA next.

What it is not, yet

Horus is research-grade. It has not been independently audited, and it should not be trusted with anything you cannot afford to lose. Its weaknesses are published in full, beside its strengths, because a security project that hides them is not making a security claim.
