Run it

From a clean checkout to a login prompt in two commands under QEMU, and from a USB stick onto a machine’s own eMMC or ATA disk.

You can have this booting on your machine in a few minutes.

An x86-64 Linux host, Debian or Ubuntu; no cross-compiler needed. This is what the boot looks like, abridged for width, and with the microsecond timestamps stripped. On a real boot every line above the banner carries one: including the lines ring 3 printed, which is the half that used to go unstamped. The console changes hands part way down that list, so both writers stamp, in one format, from one epoch. The real log is readable afterwards with dmesg.

The banner is not a constant. Everything to the right of the eye is asked of the running kernel when it prints: uptime, the tasks this caller may observe, the shell’s own pid and how many capabilities init chose to delegate to it, and the watermark of the untyped region every spawn is carved out of. Facts the shell holds no capability to ask for are left out rather than guessed at, which is why there is no line here for RAM, CPUs or the disk.

horus login:

On the live boot, log in as root / toor (an installed machine has only the accounts you created). Then try ls /bin, ps, dmesg, man hier, tcc -v, or cat /etc/motd | wc -l; the pipeline runs over a real bounded in-kernel pipe. 

# build and boot
$ rustup target add x86_64-unknown-none
$ make              # kernel.elf
$ make run          # horus.iso + QEMU
            # Ctrl-A X quits
$ make run-tpm      # with an emulated TPM
# check the claims on this page
$ make smoke                 # boot to ring-3 login
$ make smoke-captest         # 195 capability checks
$ make smoke-modules-tamper  # expect a refusal
$ make smoke-tpm-seal        # expect a locked volume
$ make reproducible-build    # run twice, diff the record

Every configuration flag, every one of the 412 test targets, and the troubleshooting notes are in BUILDING.md and TESTS.md.

Install it onto a machine's own storage.

The installer writes Horus onto a disk the machine can then boot from by itself. It installs onto eMMC, the flash soldered into many small laptops (proved on a Lenovo IdeaPad), and onto IDE and ATA disks. NVMe and SATA SSDs are not supported yet.

Build the install image and write it to a USB stick. Use install.iso, not horus.iso: only the install image has the boot menu. 

$ make install.iso
$ sudo dd if=install.iso of=/dev/sdX bs=4M status=progress conv=fsync  # sdX, not sdX1

Boot the machine from the stick. The menu's default is a live boot, which changes nothing on the machine. Choose install to write Horus to the internal disk: the installer asks for the accounts and their passwords, shows every answer on a review screen, and erases nothing until you type the confirmation word. The volume is encrypted unless you deliberately choose otherwise, and every later boot says which kind it found.

Supporting another kind of disk means writing one driver that reads and writes blocks. The encryption, integrity checks, crash safety and filesystem above it are shared by every kind of storage, so they do not change. The full procedure and its caveats are in BUILDING.md.
